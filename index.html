// CORE CAPABILITIES

Built for Terminal Power Users & Agents

01 / SPEED

Sub-10ms Startup

Zero Python runtimes, zero Docker daemons. Single statically linked Rust binary that starts in milliseconds and consumes virtually no memory.

02 / STORAGE

Normalized SQLite Engine

Raw text lives strictly once in contexts. Compact binary vectors live in embeddings. Scans numbers in RAM, fetching text only for top-k winners.

03 / EMBEDDINGS

Dual-Tier Intelligence

Leverages local Ollama (nomic-embed-text 768-dim) when online, with an automatic fallback to 256-dim subword feature hashing when offline.

04 / INTERFACE

Flexible Top-K Syntax

Query top results intuitively with shorthand flags: --1, --3, --5, or -k 10. Formatted for high readability and pipe friendliness.

05 / UNIX NATIVE

Pipes & Redirection

Fully compliant with Unix philosophy. Pipe outputs directly: cat err.log | hmc --save - --vec and redirect hmc --query "..." > context.md.

06 / PRIVACY

100% Local & Private

Your notes and memories never touch external APIs or cloud providers. Stored in ~/.hmc/hmc.db with zero tracking or telemetry.

// SYSTEM DESIGN

Normalized Two-Table Architecture

STEP 01

CLI / Stdin

Accepts raw text or pipes: hmc --save "..." --vec

STEP 02

Dual Embedder

Ollama (768-dim) or Subword Hashing (256-dim fallback)

STEP 03

SQLite (hmc.db)

contexts (Text) <--FK--> embeddings (BLOB)

STEP 04

Top-K Vector Scan

Scans binary float vectors, ranks cosine similarity, loads winning text.

// RECIPES

Common Terminal & AI Workflows

Retrieve relevant knowledge from hmc and pipe it into a local LLM in a single terminal line:

# 1. Pipe retrieved context straight to Ollama
(echo "Based on this context, summarize the key points:"; hmc --query "artificial intelligence" --3) | ollama run llama3.2

# 2. Pipe Ollama answer back into memory:
ollama run llama3.2 "Explain Docker multi-stage builds" | hmc --save - --vec

Handoff terminal context between tabs without copy-pasting:

# Tab 1: Save compilation error or server log
cargo test 2>&1 | hmc --save -
# Output: Saved context with ID: 4a7b9c1d

# Tab 2: Load in another pane or remote SSH window
hmc --load 4a7b9c1d

Add a smart recall helper function to your ~/.bashrc:

ask() {
  local query="$1"
  local context=$(hmc --query "$query" --3 2>/dev/null)
  
  ollama run llama3.2 <<EOF
Context from my notes:
$context

Question: $query
EOF
}
// DOCUMENTATION

How To Use hmc

DOC 01

Installation & Setup

Install the binary directly from GitHub using Cargo. Make sure your Rust toolchain is up to date:

BASH
cargo install --git https://github.com/khokharsnehil45/hmc
Tip for Local Embeddings: If you use Ollama, run ollama pull nomic-embed-text. If Ollama is not installed or running, hmc will automatically use its internal 256-dimensional subword hashing vectorizer with zero configuration.
DOC 02

Saving Context (Plain vs. Vector)

Save code, error messages, user preferences, or AI instructions. Use --vec when you want the context to be semantically searchable later.

SAVE COMMANDS
# 1. Plain save (stored only in contexts table): hmc --save "Temporary build configuration notes" # 2. Vector indexed save (stored in contexts + embeddings table): hmc --save "PostgreSQL GIN indexing on JSONB for sub-ms queries" --vec
On save, hmc outputs a unique 8-character hex ID (e.g., 5937969c).
DOC 03

Retrieving Context by ID

Load exact stored content using the ID provided during saving. Prefix matching allows you to type just the first few characters.

LOAD COMMANDS
# Full ID lookup: hmc --load 5937969c # Prefix match lookup (as long as it uniquely identifies the item): hmc --load 5937
If the ID matches multiple contexts, hmc alerts you with an ambiguous match error listing the candidates.
DOC 04

Semantic Querying & Top-K Matching

Query the vector store using natural language. The engine computes cosine similarity across stored vector embeddings and returns the highest-scoring matches.

QUERY COMMANDS
# Default top 3 matches: hmc --query "database indexes for fast json" # Shorthand for top 5 matches: hmc --query "artificial intelligence and machine learning" --5 # Top 1 best match only: hmc --query "sourdough bread hydration" --1
Because of the normalized SQLite architecture, vector calculations scan only compact float byte blobs in memory, fetching raw text strictly for the winning matches.
DOC 05

Unix Pipes, Stdin & Redirection

Integrate hmc into your shell scripts, CI pipelines, and LLM chains.

PIPE EXAMPLES
# Pipe command output directly into vector store: cat debug.log | hmc --save - --vec # Pipe retrieved context directly to a markdown file: hmc --query "docker networking" --3 > context.md # Pipe retrieved memory straight into an Ollama prompt: hmc --query "rust memory" --1 | ollama run llama3.2 "Explain in simple terms:"
DOC 06

Storage & Environment Variables

hmc works with zero configuration, but supports environment variable overrides:

ENVIRONMENT VARIABLES
# Custom storage directory (default: ~/.hmc/hmc.db) export HMC_DIR="$HOME/.my_custom_hmc" # Custom Ollama endpoint (default: http://localhost:11434/api/embeddings) export HMC_OLLAMA_URL="http://127.0.0.1:11434/api/embeddings" # Custom Ollama embedding model (default: nomic-embed-text) export HMC_OLLAMA_MODEL="nomic-embed-text"
// QUICK LOOKUP

CLI Command Reference

Command Description Example
--save <CONTENT> Save context to contexts table; returns 8-char ID hmc --save "User preferences"
--vec Flag to compute and index vector embedding into embeddings table hmc --save "Note" --vec
--load <ID> Retrieve raw context by full ID or prefix hmc --load 5937969c
--query <QUERY> Semantically search memory using cosine similarity hmc --query "database optimization"
--<K> / -k <K> Specify top K matches to return (e.g. --1, --5) hmc --query "rust" --5
- Read content from standard input (pipe support) cat notes.txt | hmc --save - --vec
